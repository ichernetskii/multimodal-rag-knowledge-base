# Конфигурация

`yarn configure` создаёт отсутствующие [server/.env](../server/.env.example), [client/.env](../client/.env.example) и [compose.env](../compose.env.example) из примеров. Существующие файлы сохраняются. Переменные процесса имеют приоритет перед env-файлом. Секреты и персональные файлы окружения исключены из Git.

## Кто читает настройки

| Способ запуска                                   | Источник                                                                                              |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `yarn dev`, `yarn cli`, `yarn start:server`      | Серверный launcher читает server/.env                                                                 |
| `yarn dev:client` / Vite                         | client/.env и файлы соответствующего режима Vite                                                      |
| `yarn start:client`                              | client/.env                                                                                           |
| Прямой `node server/dist/interfaces/cli/main.js` | Только окружение; для файла добавьте `--env-file-if-exists=server/.env` перед путём программы         |
| Docker Compose                                   | compose.env через `--env-file`; окружение контейнеров задаёт compose.yaml, server/.env не загружается |
| systemd / launchd                                | EnvironmentFile или аргумент Node в шаблоне службы                                                    |

Серверные относительные пути разрешаются от `server/`; пути файлов в командах CLI launcher разрешает от корня репозитория. Прямой compiled CLI использует текущий рабочий каталог для аргументов файлов. В production задавайте абсолютные пути. Клиент не читает серверные env-файлы. Переменные `VITE_*` доступны браузерному коду; для приложения они не требуются, секреты туда помещать нельзя.

## Процесс сервера и CLI

| Переменная             | Значение по умолчанию                 | Назначение                                                                                                     |
| ---------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `RAG_HOST`             | `127.0.0.1`                           | Адрес HTTP API; не влияет на адрес подключения CLI                                                             |
| `RAG_PORT`             | `3210`                                | Порт API, 1–65535                                                                                              |
| `RAG_DATA_DIR`         | `./data`                              | Первоначальный каталог данных внутри server/                                                                   |
| `RAG_BACKUP_DIR`       | Не задана                             | Переопределить backupDir при старте; относительный путь от server/                                             |
| `RAG_URL`              | `http://127.0.0.1:<RAG_PORT>`         | HTTP(S) origin для CLI без пути, credentials, query и fragment                                                 |
| `RAG_TOKEN`            | Локальный файл .cli-session           | Bearer-токен CLI; переменная имеет приоритет над сохранённым токеном                                           |
| `RAG_PUBLIC_ORIGIN`    | Origin из Host и протокола запроса    | Точный origin браузера для проверки Origin и Secure cookie; за внешним proxy задавайте явно                    |
| `TRUST_PROXY`          | Выключено                             | Только `1` разрешает учитывать X-Forwarded-Proto для HTTPS; API должен быть закрыт от прямого внешнего доступа |
| `RAG_USE_SAVED_CONFIG` | Использовать сохранённую конфигурацию | Только `0` намеренно заменяет runtime-конфигурацию значениями окружения при старте                             |

Если мастер выбрал другой каталог, `data-location.json` в первоначальном каталоге содержит указатель. Для переноса существующей установки используйте backup/restore; изменение dataDir через settings.save запрещено. Не удаляйте указатель, recovery.key или writer lock у работающего сервера.

## Модели и индекс

Embedding-профиль, репозиторий, ревизия, SHA-256 и формат входа закреплены в [model-profile.ts](../server/src/config/model-profile.ts). Произвольный embedding-репозиторий через env не выбирается. `yarn cli setup` подготавливает файлы, обычный сервер загружает только уже проверенные локальные assets. Ollama устанавливается и запускается отдельно.

| Переменная                  | По умолчанию             | Допустимые значения / смысл                                                     |
| --------------------------- | ------------------------ | ------------------------------------------------------------------------------- |
| `OLLAMA_URL`                | `http://127.0.0.1:11434` | HTTP(S) origin без пути и credentials                                           |
| `OLLAMA_MODEL`              | `qwen3.5:4b`             | Начальная модель ответа; после создания установки меняется через settings.model |
| `OLLAMA_TIMEOUT_MS`         | `300000`                 | 1000–1800000 мс                                                                 |
| `OLLAMA_KEEP_ALIVE`         | `5m`                     | Параметр keep_alive Ollama                                                      |
| `LLM_CONTEXT_TOKENS`        | `8192`                   | 512–131072 токенов                                                              |
| `LLM_MAX_OUTPUT_TOKENS`     | `512`                    | 16–8192 токенов                                                                 |
| `CONTEXT_MAX_CHARACTERS`    | `12000`                  | 1000–1000000 символов контекста                                                 |
| `EMBEDDING_CACHE`           | `./.cache/models`        | Корень локальных весов; репозиторий и ревизия добавляются автоматически         |
| `EMBEDDING_DIMENSIONS`      | `768`                    | 128, 256, 512 или 768                                                           |
| `EMBEDDING_MAX_TOKENS`      | `2048`                   | 32–2048; должен вмещать chunk с префиксом и запасом профиля                     |
| `EMBEDDING_BATCH_SIZE`      | `16`                     | 1–128 фрагментов на пакет индексации                                            |
| `EMBEDDING_THREADS`         | `4`                      | 1–64 CPU threads для query runner; индексный runner использует один             |
| `CHUNK_TOKENS`              | `256`                    | От 16 до бюджета embedding с учётом запаса профиля                              |
| `CHUNK_MAX_CHARACTERS`      | `4096`                   | 64–1000000 символов                                                             |
| `CHUNK_OVERLAP`             | `32`                     | 0…CHUNK_TOKENS−1; без env — min(32, floor(CHUNK_TOKENS/8))                      |
| `MODEL_DOWNLOAD_TIMEOUT_MS` | `600000`                 | 1000–1800000 мс на подготовку assets                                            |

Эффективный runtime сохраняется в SQLite. При следующем запуске из текущего окружения всегда привязываются каталог весов, таймаут их загрузки, адрес Ollama и число потоков CPU; остальные параметры берутся из сохранённой конфигурации. Для намеренной смены используйте `RAG_USE_SAVED_CONFIG=0`, затем диагностику и переиндексацию. Верните обычный режим после применения. Модель ответа и промпт существующей установки меняются в админке/API, а не через OLLAMA_MODEL.

Смена embedding/чанкинга может сделать индекс несовместимым: поиск вернёт `INDEX_INCOMPATIBLE` до переиндексации. Смена модели ответа/промпта не требует пересчёта векторов, но требует контрольных вопросов. Восстановление на другой машине сохраняет параметры обработки и заново привязывает физические пути/endpoint/CPU.

## PDF и OCR

| Переменная       | По умолчанию                                             | Назначение                                                                |
| ---------------- | -------------------------------------------------------- | ------------------------------------------------------------------------- |
| `PREPARE_PYTHON` | `python3`                                                | Python для создания server/.venv командой prepare:pdf                     |
| `PDF_PYTHON`     | server/.venv/bin/python3, если существует; иначе python3 | Python процесса извлечения                                                |
| `OCR_VISION_BIN` | server/.cache/ocr-vision на macOS                        | Исполняемый Apple Vision OCR; без доступного файла используется Tesseract |

```sh
yarn prepare:pdf
yarn prepare:pdf --check
yarn prepare:pdf --download
yarn prepare:pdf --offline
```

Обычный режим устанавливает [requirements-pdf.txt](../server/requirements-pdf.txt) в server/.venv и собирает локальный OCR на macOS. `--check` проверяет установленный runtime; `--download` только сохраняет wheels в server/.cache/wheels; `--offline` устанавливает их без индекса пакетов и собирает OCR. Wheels готовятся для целевой ОС/архитектуры. Tesseract и языковые пакеты устанавливаются средствами ОС; Docker включает eng/rus. Язык OCR задаётся настройкой `ocrLanguage`, например `eng` или `eng+rus`.

`PDF_EXTRACT_SCRIPT` — внутреннее переопределение пути обработчика для ресурсных тестов, не настройка формата документов. Оставляйте его незаданным в обычной установке. OCR выполняется только при непригодном текстовом слое; каждая OCR-страница требует просмотра и подтверждения.

## Клиент

| Переменная        | По умолчанию            | Назначение                                |
| ----------------- | ----------------------- | ----------------------------------------- |
| `CLIENT_DEV_HOST` | `127.0.0.1`             | Host Vite                                 |
| `CLIENT_DEV_PORT` | `5173`                  | Порт Vite; занятый порт — ошибка          |
| `RAG_API_PROXY`   | `http://127.0.0.1:3210` | API target Vite и preview, HTTP(S) origin |
| `CLIENT_HOST`     | `127.0.0.1`             | Host нативного production gateway         |
| `CLIENT_PORT`     | `8080`                  | Порт gateway                              |
| `CLIENT_API_URL`  | `http://127.0.0.1:3210` | Runtime API target нативного gateway      |

Браузер обращается к `/api` и `/health` своего origin. При смене адреса API пересборка клиентских assets не нужна: меняется proxy/gateway/nginx. Переменные CLIENT_* не настраивают nginx-образ; его upstream и порт заданы в [nginx.conf](../client/deploy/nginx.conf).

| ---------------------- | ----------------------------------- | --------------------------------------------------- |
| `CLIENT_BIND_ADDRESS`  | `127.0.0.1`                         | Host IP публикации клиента                          |

| `SERVER_CPUS`          | `4`                                 | Лимит CPU контейнера API                            |

Host-каталоги должны быть доступны UID 1000. Compose фиксирует внутри контейнера пути данных, копий, моделей и PDF runtime. Если нужны нестандартные параметры индекса, задайте их в environment сервиса, а не в server/.env. Пошаговый запуск — в [OPERATIONS.md](OPERATIONS.md#docker-compose).

## Настройки установки в SQLite

Администратор меняет их через «Настройки» или `settings.save {revision,settings}`. Можно передать только изменяемые поля; сервер объединяет их с текущими и проверяет revision. Числовые значения — целые. Новые задания используют актуальные настройки. Поля и ограничения задаёт [SettingsService](../server/src/features/settings/settings-service.ts), начальные значения — [defaults](../server/src/config/default-settings.ts).

| Поле                  | Начальное значение              | Допустимый диапазон / смысл                                          |
| --------------------- | ------------------------------- | -------------------------------------------------------------------- |
| `maxBytes`            | 26214400 (25 МиБ)               | 1024–104857600 байт на файл                                          |
| `maxPages`            | 200                             | 1–2000 страниц PDF                                                   |
| `maxTextCharacters`   | 8000000                         | 1000–32000000 символов извлечённого текста                           |
| `maxChunks`           | 20000                           | 1–50000 фрагментов на версию                                         |
| `maxDocuments`        | 10000                           | 1–100000 документов                                                  |
| `maxQueue`            | 100                             | 1–10000 незавершённых заданий                                        |
| `minFreeBytes`        | 104857600                       | 0–1000000000000 байт свободного места                                |
| `sessionHours`        | 24                              | 1–720 часов                                                          |
| `historyDays`         | 365                             | 1–36500 дней хранения истории                                        |
| `jobDays`             | 30                              | 1–36500 дней хранения завершённых заданий и результатов проверок     |
| `tempHours`           | 24                              | 1–8760 часов до очистки оставшихся extract-каталогов                 |
| `logDays`             | 30                              | 1–36500 дней технического журнала                                    |
| `eventLimit`          | 256                             | 16–1024 сохраняемых событий задания                                  |
| `backupDays`          | 30                              | 1–36500 дней хранения копий                                          |
| `backupIntervalHours` | 0                               | 0–8760; 0 отключает расписание                                       |
| `topK`                | 5                               | 1–20 источников поиска                                               |
| `ocrTimeoutSeconds`   | 60                              | 5–600 секунд на OCR страницы                                         |
| `ocrMemoryMB`         | 1024                            | 256–16384 МиБ; RLIMIT_AS применяется на Linux                        |
| `ocrLanguage`         | `eng`                           | Строчные языковые коды с `_` и `+`; пакеты должны быть подготовлены  |
| `model`               | Из OLLAMA_MODEL при создании    | Непустое имя локально подготовленной модели ответа                   |
| `prompt`              | Системная инструкция приложения | Непустой промпт; исходники документов остаются недоверенными данными |
| `backupDir`           | `<dataDir>/backups`             | Каталог, доступный пользователю API; абсолютный путь предпочтителен  |
| `pauseIndexing`       | false                           | Пауза индексации, проверяется между пакетами                         |
| `pauseQueue`          | false                           | Пауза запуска новых заданий                                          |
| `pauseIntake`         | false                           | Не принимать новые задания                                           |

`dataDir` выбирается при первом запуске; после настройки его смена требует остановки и восстановления в новый каталог. `revision` и `nextBackup` — служебные поля состояния; не используйте их для ручного планирования. Все три флага паузы имеют тип boolean. Расписания выполняются только при работающем сервере. Очистка защищает незавершённые задания; детали — в [эксплуатации](OPERATIONS.md#очереди-ресурсы-и-очистка).
