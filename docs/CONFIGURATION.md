# Конфигурация

Model profiles require `inputMicrosPerMillion: {text, image, audio, video}` and `outputMicrosPerMillion`, in integer micro-USD per million tokens. All four input keys are mandatory; scalar rates and unsupported keys are rejected. Defaults are implementation values in [default-settings.ts](../server/src/config/default-settings.ts), not a live vendor price feed; operators must verify their account's current tariff before enabling cloud profiles. Unknown input allocation is charged at the highest applicable configured rate and marked estimated; missing usage reserves the full profile context. PDF may use text/image rates; video may include audio. Redis cache hits do not create usage entries. The ledger retains the tariff snapshot and per-modality allocation, unaffected by later profile changes or tenant backup restoration.

Deployment configuration lives in private root .env, generated by yarn configure. Examples are references; do not copy placeholder passwords into production. The app runtime receives DATABASE_URL only; DATABASE_ADMIN_URL belongs to init/operator workflows. Compose supplies container-internal endpoints independently of native loopback endpoints.

Provider API keys are managed by the platform owner through the admin UI or secrets.* actions. PostgreSQL stores AES-256-GCM ciphertext; APP_ENCRYPTION_KEY stays outside the database and is required in every environment. No plaintext credential cache exists; API and workers read the current enabled credential before each provider call. AI_ALLOWED_ENDPOINTS is a comma-separated exact endpoint allowlist. A company admin can select models but cannot redirect a provider connection or read secrets. Production refuses TEST AI and requires HTTPS for credentialed provider endpoints. Test defaults must be explicitly enabled outside production.

## Company settings and model profiles

The source of truth is the [public contract](../server/src/contracts/public.ts), defaults in default-settings.ts. Settings include upload/text/page/chunk/storage caps, queue admission/pause, independent answer/index concurrency, monthly AI budget, output/context caps, cache TTL, publication processing/OCR/media limits and retention/backup schedule. Settings updates require the current revision; invalid limits fail on the server. The UI/CLI use the same API.

Profiles carry provider, role, model, modalities, dimensions, endpoint/secret reference, prices, timeout, concurrency and RPM/TPM. An indexed embedding identity is immutable: clone the profile and build a separate index. Credentials and physical deployment limits are operator configuration, not tenant-editable secrets. Google embedding requests have model-specific modality limits; context estimates are conservative guards rather than a substitute for vendor accounting.

Changing APP_ENCRYPTION_KEY makes stored API credentials unreadable and invalidates signatures of earlier tenant backups; retain the appropriate private key with protected installation backups. .env and credentials files are ignored by Git and excluded from Docker build context.

## Local AI in Docker

`LOCAL_AI` set to 1 makes `yarn docker:up` and `yarn docker:down` include compose.local-ai.yaml. `DOCKER_OLLAMA_URL` defaults to http://ollama:11434 inside the Compose network. `OLLAMA_MEMORY` (default 6g) and `OLLAMA_CPUS` (default 6) bound the inference container independently of the API and indexing workers. The `OLLAMA_PORT` host loopback port defaults to 11435 for native development (`OLLAMA_URL=http://127.0.0.1:11435`); it is not exposed on a public interface. The container disables cloud model access.

`DEFAULT_TRANSCRIPTION_PROVIDER=google` selects a Google Gemini transcription profile for new companies; it requires an active Google credential and verified prices. An empty value disables separate transcription. Existing companies choose an enabled transcription profile in company settings.

`DEFAULT_TRANSCRIPTION_PROVIDER=whisper` selects the bundled multilingual small model for new companies. Together with DEFAULT_GENERATION_PROVIDER=ollama and DEFAULT_EMBEDDING_PROVIDER=ollama, this gives new companies local profiles and their own active embedding space from creation. Environment defaults do not rewrite existing company settings. Existing companies switch through settings and a checked new index.

PDF helper paths are resolved under `server/resources/extraction`; `yarn prepare:pdf` prepares `server/.venv` and the native Apple Vision binary in `server/.cache`. These generated dependencies are separate from [sample knowledge data](../examples/knowledge-base/README.md). `PDF_EXTRACT_SCRIPT` is a test override for the extractor; it does not relocate user documents or define a second data format.

Profiles are permissions/configuration, not installers. The admin UI checks actual availability on opening and on explicit refresh. Ollama checks the named installed model, role, image capability and embedding dimensions. Whisper checks the small weights and executable. Selecting a different answer/transcription profile or starting a new index fails with a clear error when the model is unavailable. Availability is a point-in-time check, not a generation benchmark or guarantee against a later outage.

## Клиент

Client development uses CLIENT_DEV_HOST/CLIENT_DEV_PORT and RAG_API_PROXY. Native static gateway uses CLIENT_HOST/CLIENT_PORT and CLIENT_API_URL. These are public routing settings; provider keys never belong in client configuration.

Увеличение квот хранения/очереди/расходов/конкурентности и редактирование профилей моделей доступны оператору платформы. Администратор компании выбирает разрешённые профили, управляет материалами и может уменьшить свои лимиты.

API-key rotation in the owner admin needs neither environment edits nor restarts. The global vault and its audit are excluded from company backups and included as encrypted records in full PostgreSQL installation snapshots. Keep the master key separately. Provider credentials are never returned through HTTP/CLI, written to audit or stored in Redis and job payloads.
