# Локальные модели в Docker — проверка 16 октября 2026

> Исторический отчёт: описывает проверенный на тот момент код. Актуальные инструкции — в [документации](../README.md); новый прототип — в [спецификации админки](../ADMIN-UX.md).

Подключение завершено на текущем Intel Mac. Работающая установка: http://localhost:8080, Compose-проект `local-rag-saas-app`. Обе компании Demo A и Demo B используют Qwen3.5:4b для ответов, EmbeddingGemma для поиска и встроенный Whisper small для речи. TEST-профили выключены. Существующие документы сохранены, активные поисковые индексы перестроены на EmbeddingGemma (768 измерений).

## Что изменено

- `compose.local-ai.yaml`: отдельный Ollama, постоянный том `ollama-data`, автоматический инициализатор Qwen3.5:4b и EmbeddingGemma. Ollama и образ инициализатора зафиксированы версией 0.40.5 и digest. При повторном запуске установленные модели переиспользуются без скачивания.
- `LOCAL_AI=1`: штатная команда `yarn docker:up` выбирает локальный набор автоматически. Для новой установки предусмотрено `yarn configure --local-ai`. Сервер получает внутренний адрес `http://ollama:11434`; отдельный порт хоста 11435 привязан к loopback и доступен для native-разработки. Уже работающий пользовательский Ollama на 11434 не останавливался и не изменялся.
- Whisper small, FFmpeg и whisper.cpp уже входят в серверный образ. Теперь профиль Whisper включён и выбран в настройках обеих существующих компаний; новые компании получают его из DEFAULT_TRANSCRIPTION_PROVIDER.
- В админке доступны автоматическая проверка при открытии, повторная проверка одной модели и проверка всех моделей. Состояния «Проверяем», «Доступна», «Недоступна», время проверки и конкретная причина показаны в читаемых карточках. В настройках виден статус выбранных моделей. Подключение к Ollama само по себе не считается наличием модели: проверяются имя, задача, поддержка изображений и размерность embeddings. Для Whisper проверяются веса small и запуск программы.
- Сервер отклоняет смену модели ответа/распознавания и создание индекса с недоступным подключением. CLI `yarn cli models status [id] --json` использует ту же проверку.

## Реальный сценарий

[Машинный отчёт](local-ai-2026-10-16.json), `success: true`. Использовались настоящие локальные модели, без платных API и без TEST AI. В Demo A оставлены явно обозначенные учебные материалы: текстовая инструкция, фото сервисной этикетки, аудиозапись и видео.

| Проверка | Результат |
| --- | --- |
| Текст → публикация → EmbeddingGemma → поиск → Qwen/SSE | Верный ответ: фильтр учебного насоса заменяется каждые 45 дней, со ссылкой `[1]`. |
| Повтор того же вопроса | Точное попадание в кеш Redis, модель повторно не вызывалась. |
| Фото → описание Qwen → EmbeddingGemma → поиск и ответ по изображению | Прочитаны модель AX-100, ошибка E-42; ответ по фото верно указал 12 Нм. |
| Аудио → Whisper → EmbeddingGemma → поиск и ответ Qwen | Получена правильная расшифровка фрагмента JFK и ответ с источником. |
| Видео → FFmpeg/кадр → Qwen → EmbeddingGemma → поиск и ответ | В ответе верно указан код E-42 со ссылкой на видео. |
| Отсутствующая модель при работающем Ollama | Возвращена понятная ошибка о незагруженных весах; замена рабочей модели отклонена. |
| CLI | Подтверждены включённые и доступные Qwen, EmbeddingGemma и Whisper. |

Времена относятся к одному короткому учебному сценарию на CPU и включают очередь, поиск и выдачу через SSE. Это не нагрузочный тест или гарантия для других материалов.

| Ответ | До первого текста | Полный ответ |
| --- | --- | --- |
| Текстовая инструкция, без кеша ответа | 16,3 с | 25,6 с |
| Тот же вопрос, кеш Redis | 0,31 с | 0,33 с |
| Фото | 78,8 с | 92,2 с |
| Аудио после индексации | 24,6 с | 33,0 с |
| Видео после индексации | 39,8 с | 49,7 с |

Предварительная подготовка материалов учтена отдельно в JSON: фото целиком с индексацией и ответом заняло около 143 с, аудио — 67 с, видео — 95 с. Первый запуск дополнительно скачивает несколько ГБ образов и весов. Docker имеет 8 ГБ памяти; Ollama ограничен 6 ГБ, одним параллельным запросом, одной резидентной моделью и контекстом Qwen 8192. Во время обработки изображения наблюдалось около 3,9 ГБ памяти контейнера и нулевое использование GPU. В демонстрационных компаниях установлен короткий лимит ответа 256 токенов.

## Перезапуск, отсутствие сети и интерфейс

[Проверка без сети](local-ai-offline-2026-10-16.json): отдельный контейнер с `--network none` и томом весов только для чтения успешно выполнил тот же инициализатор за 2,5 с; обе модели уже установлены. Это проверка доступности сохранённых файлов, а не время генерации. Отчёт содержит точные digest и размеры обеих моделей.

[Проверка перезапуска](local-ai-restart-2026-10-16.json): после остановки/запуска Ollama выполнен новый ответ через SSE за 25 с. Qwen правильно ответил: «В учебном примере отпуск нужно запрашивать за 14 календарных дней [1]». Проверены автоматические локальные настройки новой компании; пустая тестовая компания затем удалена.

В браузере проверены рабочие статусы моделей, выбранные Qwen/Whisper и активный embedding-профиль; при остановке Ollama проверка показала [понятное сообщение об отсутствии соединения](local-ai-unavailable-2026-10-16.png). После запуска доступность восстановилась. [Рабочие настройки](local-ai-settings-2026-10-16.png). Ошибок в консоли браузера при проверке нет.

Полная проверка `yarn validate`: документация, контракты, TypeScript, ESLint, форматирование, 20 серверных тестов, 22 клиентских теста и обе сборки. Отдельный [интеграционный сценарий](local-ai-integration-2026-10-16.tap) прошёл с настоящими PostgreSQL, pg-boss, S3 и Redis. Его тестовые компании и файлы удалены из отдельной среды native-разработки. Один первоначальный запуск копирования превысил 60-секундный тестовый дедлайн во время параллельной тяжёлой сборки; после её завершения полный сценарий прошёл за 12,3 с без изменения таймаута.

## Перенос на другой сервер

Ручная установка Ollama, Whisper или FFmpeg на хосте не нужна. Нужны Docker/Compose, подходящие CPU/RAM/диск, файлы развёртывания и приватный `.env`. Данные клиентов переносятся через PostgreSQL/S3 резервные копии. Веса Ollama переносятся отдельным томом или скачиваются инициализатором заново. Обычная копия БД/S3 не содержит этот том. Для точного и автономного переноса сохраняйте существующие веса и их digest; после смены embedding-весов индекс необходимо перестроить.

Порядок запуска и переноса описан в [разработке](../DEVELOPMENT.md), [конфигурации](../CONFIGURATION.md) и [эксплуатации](../OPERATIONS.md). Настройка публичного домена/HTTPS и GPU на другом сервере зависит от окружения и этой проверкой не подтверждается. Качество и скорость проверены только на перечисленных учебных материалах текущего компьютера.
