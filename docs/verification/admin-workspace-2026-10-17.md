# Реальная админка и чтение материалов — 17 октября 2026

Этот отчёт относится к переносу согласованного прототипа в React и изменениям API текущей рабочей копии после 23d2e09. Прототип на Sites не является исполняемой админкой. Проверки ниже выполнены на отдельной временной установке; существующая БД разработки с предыдущей схемой сохранена.

## Проверено в браузере

Production-сборка React обслуживалась настоящим gateway и HTTP API на случайном loopback-порту. PostgreSQL, Redis, S3 и pg-boss работали реально. Отдельные БД и bucket созданы тестовым helper, роли заданы отдельными аккаунтами. Модели ответов/embeddings — TEST AI, декодеры и Whisper — настоящие.

- Оператор: одно постоянное меню с областями компании/платформы, назначения и подключения моделей. Внешние API отделены от своих серверов. Google ASR имеет отдельную задачу и выбор общего ключа; отключённый ключ недоступен для выбора.
- Платформенные ключи и диагностика: переключателя компании нет, область «Вся платформа». Диагностика показывает PostgreSQL, Redis, S3, worker и PDF/OCR/FFmpeg/Whisper, одна кнопка обновления.
- Смена компании: пустая компания не содержит материалов предыдущей. Выбранный раздел сохраняется.
- Администратор компании: доступны назначения, но отсутствуют вкладка редактирования подключений и ключи платформы.
- Редактор с edit-доступом: доступны загрузка, проверка и подключённые папки; административных разделов нет. Выбор существующего it.txt через file chooser показывает «Содержимое уже есть».
- Читатель: нет загрузки, исправлений, проверки, административных вкладок; черновики скана и повреждённого PDF не видны. Опубликованный исправленный TXT доступен.
- Длинный TXT: 32119 символов до исправления, первое окно 12000. Поиск P-204 находит четыре совпадения, включая конец документа; выбор последнего загружает окно 27180–32119 и выделяет код. Запрос отсутствующей фразы явно показывает отсутствие совпадений.
- Исправление последнего окна сохраняется через API, затем публикация/индексация принимаются в очередь. Итоговый текст — 32150 символов. Читатель открывает уже опубликованный результат.
- Ошибка повреждённого PDF в списке содержит причину «Файл не является PDF».
- Читатель на 390 и 320 px: body.scrollWidth совпадает с шириной viewport, диалог 356 и 286 px соответственно. Текст переносится без горизонтального переполнения. Кнопок исправления у читателя нет.
- В проверенной сессии консоль без warning/error. Снимки текущего запуска сохранены в игнорируемом `.artifacts/verification/admin-workspace.png` и `admin-mobile.png`.

Все девять материалов общего корпуса загружены и обработаны в этом окружении: MD, TXT, четыре вида PDF, PNG, WAV и MP4 с аудио. Восемь опубликованы helper, скан оставлен на проверке. Дополнительный длинный TXT проверен/опубликован через UI; повреждённый PDF оставлен для проверки ошибки. Полная обработка медиа сначала обнаружила устаревший native FFmpeg без libx264; после подготовки текущего runtime видео прошло.

## Автоматизированная проверка

`yarn validate` прошёл: документация (29 Markdown, 85 действий, 35 команд, 42 переменные окружения), сгенерированные контракты, TypeScript всех проектов, ESLint, Prettier, production-сборки. Сервер: 36 тестов прошли, один integration-test штатно исключён из unit-набора. Клиент: 33 теста прошли. После финальной правки подсказки для читателя клиент повторно собран.

`yarn test:integration` прошёл на локальных PostgreSQL/Redis/S3. Включены регрессии подготовленного текста при нулевом лимите binary-media и большого личного вложения с релевантной информацией в конце. Для длинного фикстурного файла квота TEST embeddings увеличена только в временной компании: сценарий проверяет контекст, а не ожидание default rate window. При первоначальном прогоне с default-квотой индексация корректно ожидала лимит; уже записанные chunks не вычислялись заново.

`yarn test:docker` прошёл все 12 этапов: сборка, холодный запуск, авторизация и компании, multipart/review/index/search, очередь и SSE после рестарта API, реальные PDF/OCR/PNG/WAV/MP4, импорт девяти файлов, исправление опубликованной версии, потеря Redis, targeted backup/restore, закрытое S3 и диагностика. Машинные логи текущего запуска: `.artifacts/verification/validate.log`, `integration.log`, `docker.log`, `docker.json` (success=true). Предыдущий промежуточный Docker-прогон остановился на несовпадении формата CLI после изменения контракта во время сборки; итоговый прогон выполнен с согласованным контрактом, без адаптеров старого формата.

Интеграция проверяет ограниченность HTTP-ответов на больших версиях, literal find/пагинацию/Unicode, сохранение остальной страницы при правке/удалении диапазона и отклонение повреждённого Unicode, unpublished replacement, сортировку и literal filename filters, запрет черновиков/asset после отзыва edit, скрытие sync path, tenant RLS, очереди, учёт, качество и backup/restore. Отдельный сценарий проверяет повторное использование автоматически подготовленного текста при смене модели поиска и сохранение активного индекса при сбое подготовки. Протокол Google transcription проверяется локальным HTTP fixture, включая payload/расход; это не проверка реального Google-аккаунта.

## Ограничения и воспроизведение

`yarn build:client && yarn test:workspace` создаёт такое же независимое окружение и печатает URL/учебные логины. Ctrl+C завершает обработчики и удаляет только принадлежащие helper ресурсы. `yarn test:integration` и `yarn test:docker` создают свои ресурсы самостоятельно. Актуальная схема/tenant-data-v3 отклоняет прежние форматы; существующая установка не мигрируется и автоматически не очищается.

Платные вызовы Google/Anthropic и фактическая точность их ответов не выполнялись. В браузере не выполнялись необратимые удаления секретов или изменение реальных прав/аккаунтов. Ротация ключей, отказ инфраструктуры, конкурентные revision и restore проверяются API/Docker-сценариями. Производительность ARM/M4 из этой проверки не следует. Исторический [локальный AI отчёт](local-ai-2026-10-16.md) описывает отдельные реальные модели и не подменяет текущую проверку.

Временные Docker-тома и контейнеры проверок удалены; отдельно остановлена сохранённая промежуточная установка. Удалена оставшаяся прерванная сборка медиатулов (418 МиБ), рабочие инструменты/веса сохранены. Заменённые React overview и стили удалены. Существующие установки разработки и их данные не сбрасывались.


## Дополнительный сценарий: исправления опубликованного материала

Добавлен documents.revise и CLI revise. В браузере под редактором опубликованная jfk.wav скопирована в новую версию для проверки, в расшифровку добавлена учебная пометка, сравнены две версии и принята публикация исправления. Прежний текст показан отдельно; копирование не меняет источник. Снимок сравнения: `.artifacts/verification/admin-correction.png`.

API-сценарий использует настоящий S3 и три разных файла (MP4, PNG preview, WAV). Проверены новые независимые asset IDs/object keys и SHA, сохранение прежней activeVersion до публикации, недоступность кандидата читателю, один успех при конкурентных revision, изменение только нового текста, отсутствие новых usage-ledger записей при копировании, отказ S3 и повтор без дубликатов. При storage quota создание кандидата откатывается без изменения версии/ревизии. Отдельный Docker-этап проверяет создание/исправление/публикацию, после чего backup/restore охватывает обе версии.

Дополнительно через настоящий CLI загружен временный MKV (remux учебного MP4), обработанный управляемыми FFmpeg/Whisper. В браузере проверены подготовленные MP4/WAV-ресурсы вместо исходного контейнера и отдельная ссылка к времени оригинала. В плеер добавлено сообщение о недоступном предпросмотре; regression tests проверяют отсутствие исходного временного сдвига внутри уже нарезанного клипа. Сгенерированный MKV не добавлен в фиксированный корпус.

Финальная браузерная проверка: переименование тестовой компании сразу обновило переключатель, аудио опубликованной исправленной версии загрузилось (duration=11, readyState=4), подготовленный MP4 для MKV загрузился (readyState=4). На 320 px после загрузки медиа dialog.scrollWidth=dialog.clientWidth=284, body.scrollWidth=320; длинное предупреждение занимает 240 px и переносится. Команда CLI revise выполнена на опубликованной учебной аудиозаписи. Консоль финальной сессии без warning/error.
