# Документация

Документы описывают текущий код проекта. Исторические протоколы проверок имеют собственные даты и не означают повторного запуска на каждом изменении. До первого релиза действуют [правила без обратной совместимости](../AGENTS.md).

| Задача                                                      | Документ                                                   |
| ----------------------------------------------------------- | ---------------------------------------------------------- |
| Установить и впервые открыть приложение                     | [Быстрый запуск](../README.ru.md), [English](../README.md) |
| Загрузить документ, найти источник, вести диалог            | [Использование](USAGE.md)                                  |
| Настроить окружение разработчика и команды                  | [Разработка](DEVELOPMENT.md)                               |
| Выбрать переменные окружения и лимиты                       | [Конфигурация](CONFIGURATION.md)                           |
| Работать из терминала и восстановить администратора         | [CLI](CLI.md)                                              |
| Интегрироваться с HTTP, SSE и обработать ошибки             | [API](API.md)                                              |
| Понять модули, хранение, доступ и ресурсные границы         | [Архитектура](ARCHITECTURE.md)                             |
| Развернуть службы, сделать копию, восстановить или обновить | [Эксплуатация](OPERATIONS.md)                              |
| Повторить проверки и оценить границы результатов            | [Проверка](VERIFICATION.md)                                |
| Сопоставить требования 11–21 с реализацией                  | [Матрица требований](REQUIREMENTS.md)                      |

Краткие указатели workspace: [клиент](../client/README.md), [сервер](../server/README.md). Источники истины: [публичный контракт](../server/src/contracts/public.ts), [настройки по умолчанию](../server/src/config/default-settings.ts), [проверка настроек](../server/src/features/settings/settings-service.ts), [команды проекта](../package.json).

Изменяя поведение, обновляйте соответствующий документ, примеры окружения и проверки вместе с кодом. `yarn docs:check` проверяет локальные ссылки и разделы, полноту списка API actions, команд проекта и переменных из файлов-примеров. `yarn validate` включает эту команду. Снимки UI и измерения находятся в [verification/](verification/); их исходные даты сохраняются.
