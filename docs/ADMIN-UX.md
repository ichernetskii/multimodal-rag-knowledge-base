# Новая админка: прототип и спецификация

Статус: интерактивный прототип для будущей реализации, уточнён 16 октября 2026 года. Текущие страницы React описаны в [USAGE](USAGE.md); предложенная ниже навигация ещё не заменяет их. Прототип использует учебные данные и локальную симуляцию действий; оригиналы PNG, скана, WAV и MP4 взяты из учебного корпуса. Он не проверяет сервер, не сохраняет значения ключей и не подтверждает доступность моделей.

## Проблемы текущего интерфейса

Выбор модели ответа, модель поиска, API-ключ и профиль подключения находятся в разных разделах. Пользователь видит внутреннее понятие индекса до объяснения задачи. Платформенный реестр ключей соседствует с каталогом моделей выбранной компании, но область изменений легко пропустить. Загрузка, проверка, публикация и включение в поиск выглядят как разные технические операции. Успешное соединение с сервером моделей не означает готовности материала к поиску.

## Структура

| Раздел           | Содержимое и область                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| База знаний      | Список баз → материалы, доступ, подключённые папки, качество; обработка/публикация и ошибки внутри материала |
| AI и модели      | Назначения «Ответы», «Поиск», «Распознавание записей», инструкция; владельцу доступны подключения и ключи    |
| Команда и доступ | Участники, приглашения, группы выбранной компании; права на конкретную базу также доступны внутри базы       |
| Расходы и лимиты | Использование, бюджет, ресурсы и сроки хранения выбранной компании                                           |
| Обслуживание     | Задания, резервные копии, журнал и параметры обработки выбранной компании                                    |
| Платформа        | Постоянная группа operator: API-ключи и состояние системы; меню компании остаётся видимым                    |

Выбор рабочей компании находится в шапке только в контексте компании. При открытии общих ключей или состояния системы он скрывается; шапка и подвал показывают «Вся платформа». Меню остаётся одним и тем же: постоянная группа «Компания …» с рабочими разделами и группа «Платформа · все компании» с общими ключами и состоянием системы. Отдельного меню платформы, кнопки возврата и каталога ссылок «открыть компанию» в прототипе нет. Компания не становится названием платформенного реестра: у каждого изменяемого блока видна область «Компания …» или «Все компании». Уход со страницы с несохранённой формой или переключение компании требует решения о несохранённых изменениях. Нет второго независимого меню админки с теми же пунктами.

Название группы меню «Рабочее пространство» постоянно при смене демо-роли. Меняется доступный набор действий; платформенная группа видна только владельцу. Подвал показывает область действия и текущую роль. Демо-переключатель вынесен за оболочку продукта в блок «Демонстрация интерфейса» с объяснением учебных данных и отсутствия реальных API-вызовов; в продукт он не переносится. В прототипе Demo B начинается без материалов; назначения, добавленные профили, инструкция, бюджет и параметры обработки не копируются из Demo A. Общий реестр ключей остаётся общим намеренно.

## AI: один рабочий экран

Основной экран — назначения задач. Каждая строка содержит назначенную модель, поставщика, поддерживаемые входы, состояние, причину блокировки и следующее действие. Настройки инструкции/контекста раскрываются ниже без перехода в другой раздел. Подключения — соседняя вкладка владельца. Назначения выбирают готовые профили компании; подключения сгруппированы «На вашем сервере» и «Через внешний API». На облачной карточке видны ссылка на общий ключ и его состояние. Ключ редактируется через постоянный пункт «API-ключи», а рабочие разделы остаются в меню.

Владелец выбирает поставщика и готовый общий API-ключ в профиле, задаёт endpoint/model/capabilities/цены, проверяет соединение и сохраняет профиль компании. Если ключ отсутствует, он создаётся в постоянном разделе «API-ключи», с явной областью всех компаний. Базовые поля видимы, тарифы и технические лимиты сгруппированы в раскрываемые блоки. Локальному поставщику не показывается обязательное поле ключа. Поддержка модальностей проверяется адаптером, а не обещается галочкой.

«Добавить подключение» создаёт профиль конкретной модели в каталоге компании. Профиль появляется в списке соответствующей задачи; это не добавление произвольного API-протокола. В текущем сервере Google поддерживает генерацию и embeddings, Anthropic — генерацию, Ollama/совместимый API — текстовые embeddings и текст/изображения для генерации. Endpoint указывает адрес API, дополнительно ограниченный allowlist установки. Capabilities описывают входы/выходы и задачи реальной модели. Цены по модальностям нужны для оценки расхода и контроля бюджета; они не оформляют подписку у поставщика. Прототип явно обозначает сохранение профиля как учебное и не выдаёт его за проверку соединения.

«Распознавание записей» создаёт расшифровку загруженного аудио и звуковой дорожки видео. Это не синтез речи и не голосовой чат. Отдельная ASR-задача реализована локальным Whisper small и Google Gemini через API. Gemini Embedding по аудио возвращает вектор; Gemini с назначением transcription возвращает текст. Это разные профили и задачи. При мультимодальном аудиопоиске расшифровка необязательна; если профиль ASR выбран, сервер её всё равно выполняет. При текстовом поиске отключённая расшифровка блокирует обработку аудио: интерфейс должен объяснять эту связь.

После сохранения секрет очищается из поля и состояния формы. Сохранённое значение нельзя показать ни одной роли. Видны alias, поставщик, enabled, число ссылок и аудит. Отключение явно предупреждает об области всех компаний; удаление возможно лишь без ссылок. Проверка соединения помечается временем и не называется проверкой качества. Запросы проверки не запрашивают платную генерацию; отдельный пробный ответ требует явного действия с предупреждением о расходе.

Ответы и речь сохраняются независимо от поисковой модели. Для поиска выбор создаёт предложение замены: «Подготовить новый поиск» → построение → пробный запрос/просмотр результата → «Использовать новый поиск». Старый поиск продолжает работать. Ошибка построения, недоступная модель или изменение корпуса блокирует переключение и предлагает повторное построение. Термин «индекс» остаётся в подробностях. Нужна видимая отмена несохранённого выбора. Устаревшая ревизия возвращает конфликт с перезагрузкой актуальных данных, без скрытого перезаписывания.

## База знаний

Первый экран объясняет назначение базы и предлагает добавить первый материал. Внутри базы основные вкладки: материалы, доступ, источники/папки и качество. Модель поиска — ссылка на соответствующую строку AI, а не ещё одна независимая форма выбора.

Путь материала: загрузка → обработка → нужна проверка → индексация → доступен для поиска. «Сохранён» не равен «доступен в поиске». Для каждого этапа показываются результат, причина ожидания/ошибки и доступное действие. «Исключён из поиска» отличается от ошибки обработки. Общий фильтр «Требуют внимания» объединяет review/failed/interrupted; рядом сохраняется исходный статус.

Проверка открывается в контексте материала: оригинал или медиа, извлечённый текст, страницы/таймкоды, предупреждения, способ извлечения и версия. Для аудио/видео обязательно различаются речь и визуальное описание. Подтверждение публикации доступно редактору с edit grant или администратору; пользователь читает только опубликованное. Замена файла оставляет текущую опубликованную версию доступной до явного переключения. Массовая публикация перечисляет конкретные документы и требует подтверждения проверки каждого; автоматический импорт не считается ручной проверкой.

Кнопка называется «Проверить обработку». Справа показывается результат обработки с действием «Исправить текст обработки» для редактора до публикации. API documents.correct меняет OCR/описание/расшифровку, сохраняя оригинал, сбрасывает подтверждение и требует актуальную revision. Принятая публикация блокирует дальнейшую правку. Опубликованные версии исправляются новой версией. Слева — оригинал: изображение/страница PDF, аудио- или видеоплеер. Отдельный экран читателя содержит переключатель страниц/сегментов; длинный текст показывается по разделам, с переносами строк и поиском внутри материала. Поиск в прототипе действительно перебирает все разделы учебного материала, показывает число совпадений, фрагменты, переходы и подсветку; отсутствие результата показано явно. Чтение использует обычную типографику и абзацы, а не моноширинный pre. Для будущей реализации нужно добавить серверную загрузку отдельных страниц: текущий documents.read возвращает страницы всей версии, а переключатель клиента сам по себе не решает объём ответа API.

В карточке медиа коротко показано, какие данные используются для поиска. В текстовом читателе нет технической цепочки «текст → фрагменты → векторы»: она не помогает чтению. С текстовой embedding-моделью используются OCR, машинные описания изображений/превью и расшифровки. С мультимодальной — бинарное содержимое подготовленных изображений, видеоклипов и звуковых сегментов; описание каждого медиа словами не требуется. PDF в текущем конвейере — текст/OCR плюс изображения страниц, а не передача всего PDF в embedding API. Наличие текста рядом с оригиналом не доказывает текстовый режим. Режим определяется активным индексом, а не ещё не применённым выбором модели. Подробности и ограничения — в [MEDIA](MEDIA.md).

Доступ настраивается у базы: пользователь/группа, read/edit, пояснение роли. Редактору нужен edit grant; роль editor сама по себе доступ не выдаёт. Администратор компании не получает чужие личные вложения и чаты. Отзыв прав обновляет список, поиск, файл и исторические цитаты.

## Роли

| Роль                   | Доступ                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Пользователь           | Чат, чтение разрешённых опубликованных материалов и источников; без админки                                                |
| Редактор               | Дополнительно загрузка, проверка и публикация в базах с edit grant; без глобальной админки                                 |
| Администратор компании | Команда, базы/ACL, выбор разрешённых моделей, настройки, обслуживание своей компании; снижение квот                        |
| Operator               | Дополнительно компании, общие ключи, профили/цены/endpoint, инфраструктура и увеличение квот; контент по текущему членству |

Operator — отдельный флаг, а не четвёртое значение role. Меню помогает ориентироваться; сервер независимо проверяет каждую операцию. Прототипный переключатель ролей служит только для просмотра дизайна.

## Обслуживание и область настроек

Внутри компании: задания с этапами/причинами ошибок и допустимым повтором; резервные копии с проверкой целостности и восстановлением текущего формата; журнал действий; обработка и сроки хранения. Восстановление требует отдельного подтверждения замены данных выбранной компании. Копия компании не переносит общие ключи и глобальные аккаунты; расходы и действующие операторские ограничения не откатываются. Кнопки копирования/восстановления в прототипе выполняют только симуляцию.

Материалы, доступ, участники, назначения и профили моделей, инструкция, бюджеты, параметры обработки, история, задания и копии относятся к компании. Общие API-ключи и их аудит, инфраструктура, разрешённые endpoint, установленные runtime и жёсткие CPU/RAM-пределы относятся к платформе. Администратор компании не редактирует общие секреты. Собственные ключи каждой компании (BYOK) были бы отдельным изменением модели владения и API; прототип не объявляет эту возможность реализованной.

## Ошибки и состояния

| Состояние                             | Сообщение и действие                                                                                   |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Нет ключа / ключ отключён             | Назвать подключение; владельцу — добавить/заменить ключ здесь, администратору — обратиться к владельцу |
| Модель не установлена                 | Указать модель и сервер; владельцу — проверить/подготовить runtime, остальным — кто должен исправить   |
| Нет поискового индекса                | Объяснить необходимость публикации/построения; кнопка подготовки поиска по правам                      |
| Модальность не поддерживается         | Назвать файл, модальность и выбранный профиль; выбрать совместимый конвейер                            |
| Не хватает бюджета                    | Использовано/лимит и период; кто может увеличить квоту; повтор не обещает успех                        |
| Нет обработчика / приём приостановлен | Задание сохранено, причина ожидания и ссылка на состояние по правам                                    |
| OCR/расшифровка требует проверки      | Страница/таймкод, предупреждение и просмотр оригинала; не требовать ручного описания при native-медиа  |
| Неизвестный результат платного вызова | Не повторять автоматически; проверить расход у поставщика перед ручным повтором                        |
| Сетевая ошибка / недостаточно прав    | Разделять временную недоступность и отказ доступа; diagnostic ID, время и безопасный повтор            |

Состояния loading/empty/unavailable/disabled/error/success не заменяются друг другом. Зелёный статус модели не означает активный индекс. Сообщения не содержат ключи, тела ответов провайдера или текст закрытого документа.

## Реализация и приёмка

1. Заменить структуру навигации и маршрутизацию одной реализацией; обновить тесты прав, прямых ссылок и переключения компании. Не сохранять алиасы старых разделов.
2. Составить AI workspace из независимых запросов моделей, настроек, индексов и operator-only реестра. Ошибка реестра не блокирует чтение назначений для company admin. Формы сохраняют только свои поля и текущую revision.
3. Переиспользовать credentials editor внутри формы подключения; после сохранения обновлять список и проверки. Проверить отсутствие значения секрета в DOM после submit, localStorage, уведомлениях и трассах.
4. Перенести построение/активацию поиска в строку назначения с сохранением серверных indexes.build/activate и проверки корпуса. Потеря страницы не теряет принятое задание.
5. Объединить материалы и управление базой общим контекстом; статусы извлечения/проверки/публикации получать из сервера. Сохранить скачивание, замену/сравнение версий, preview и provenance.
6. Проверить свежую компанию без моделей/ключей/документов, все четыре уровня доступа, disabled/удалённый профиль, отсутствие runtime, отказ S3/Redis/worker, лимит бюджета, 409 и отмену задания.
7. Пройти весь [учебный корпус](../examples/knowledge-base/README.md): загрузка всех модальностей → review → публикация → поиск → источник → замена → отзыв ACL → backup/restore. Проверить 320/390/1024 px, клавиатуру, focus, label и live-статусы.

Контракт HTTP и криптография остаются проверяемыми серверными механизмами. Если для составного статуса потребуется новый API, сначала добавить типы, валидацию и документацию в public.ts, затем сгенерировать клиент. Фактическую приёмку React и реального AI описывать отдельным отчётом после реализации; работа прототипа её не заменяет.

Сохранённый текст материала не меняется при переключении модели в прототипе. Меняется маршрут поиска; для нового индекса используется сохранённый текст и поддерживаемое медиа. Прототип не должен изображать исчезновение расшифровки при отключении ASR или включении native-поиска.

## Уточнение обработки и навигации

Недостающий текст автоматически создаётся во время подготовки нового текстового индекса. Сохранённый текст не пересчитывается при выборе другой embedding-модели. Модель ответов с поддержкой изображений готовит описания, отдельное назначение ASR готовит речь. Нужны только два назначения обработки, без второго скрытого выбора модели для описаний. В строке ответов эта дополнительная функция названа явно. Результаты генерации сохраняют профиль/модель/время и должны быть проверены перед включением поиска.

Поиск по открытому материалу — второстепенное действие «Найти в этом документе», аналог Ctrl+F, без обращения к AI. Показаны область поиска, примеры существующего кода, число совпадений, фрагменты и отсутствие результатов. После поиска результаты прокручиваются в видимую область. Текст занимает всю ширину читателя с нормальной шириной строки; скрытая панель не оставляет пустую вторую колонку.

«Состояние системы» содержит одну кнопку обновления и статусы API, обработки, хранения и локальных моделей. Технические зависимости раскрываются без ещё одного диалога/кнопки проверки. Прототип не проверяет реальные зависимости и обозначает учебный результат.

Форма подключения сначала определяет размещение/поставщика и задачу. Для Ollama основные поля — адрес сервера и установленная модель; для Whisper — встроенная small и параметры обработки (язык/CPU). Для внешнего API — поставщик, модель и разрешённая ссылка на ключ платформы. Адреса внешних API имеют значения по умолчанию. Контекст, входные модальности, размер/длительность, параллельность, RPM/TPM и таймаут относятся к раскрываемым параметрам; ставки входа/выхода нужны облачному бюджету. Указание capabilities не заменяет проверку адаптера.
