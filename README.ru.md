# Knowledge Workspace: общий SaaS

Один сервер обслуживает несколько компаний. Каждая компания имеет свои базы знаний, документы, участников, настройки, профили моделей, расходы и задания. Учётная запись может состоять в нескольких компаниях; переключение не переносит данные между ними. PostgreSQL RLS дополняет проверки прав в приложении.

Файлы хранятся в локальном S3 — SeaweedFS в Docker-томе вашего сервера. Для облачного S3 можно сменить endpoint и ключи. Redis ускоряет повторные запросы; данные и очередь сохраняются в PostgreSQL. Воркеры Node.js разбирают материалы, строят индекс, вызывают AI, сохраняют ответ и выполняют обслуживание. API принимает запрос и возвращает ID задания, клиент получает состояние и части ответа через SSE.

## Запуск для разработки

```sh
yarn install --immutable
yarn configure
yarn infra:up
yarn cli init
yarn seed
yarn dev
```

Нужны Node.js 24.19+ и работающий Docker Compose. Откройте http://localhost:5173, логин `admin`, пароль `local-development-only`. Это демонстрационный аккаунт только для разработки. По умолчанию два демонстрационных пространства создаются с TEST AI: детерминированным тестовым провайдером без платных вызовов. Чтобы получать настоящие ответы, настройте модель, секрет на сервере, возможности и цены в профиле.

После входа через CLI и выбора компании выполните `yarn demo:import`: появится отдельная учебная база с текстом, PDF, сканами, табличкой, аудио и готовым видео. Материалы останутся на проверке; просмотрите извлечение и подтвердите публикацию. [Описание корпуса и контрольные вопросы](examples/knowledge-base/README.md). Seed создаёт только аккаунт и компании.

Для целиком контейнерного запуска выполните `yarn docker:up`, затем запустите `seed` внутри контейнера API; [команды](docs/DEVELOPMENT.md) приведены в документации разработки. Откройте http://localhost:8080. Настоящее развёртывание описано в [OPERATIONS](docs/OPERATIONS.md).

Старые SQLite, API и настройки не поддерживаются. Схема несовместимого релиза отклоняется. Сброс разработки выполняется отдельной командой с явным флагом; она затрагивает только Docker-проект разработки.

`client/src` содержит браузерный код; `server/src` — API, воркеры и CLI; `server/resources` — необходимые PDF/OCR-ресурсы. Команды разработки находятся в корневом `tooling`, учебные данные — в `examples`. Новые временные отчёты записываются в `.artifacts/`, проверенные исторические отчёты — в `docs/verification/`. [Структура админки](docs/ADMIN-UX.md) реализована в React и использует публичный API; сценарии описаны в [USAGE](docs/USAGE.md).

Для новой установки с настоящими локальными моделями используйте `yarn configure --local-ai`, затем `yarn docker:up` и seed внутри API. Ollama автоматически загрузит Qwen3.5:4b и EmbeddingGemma в постоянный том; Whisper small встроен в серверный образ. Выбор модели и её доступность показаны в админке «AI и модели → Назначение моделей»; подключения — в соседней вкладке «Подключения», а общие секреты — в разделе платформы «API-ключи». Подробности ролей и разделов — в [руководстве пользователя](docs/USAGE.md). Порядок переключения существующих компаний и перенос томов описаны в [разработке](docs/DEVELOPMENT.md) и [эксплуатации](docs/OPERATIONS.md).
