# Local RAG

Автономная библиотека документов с поиском, чатами, пользователями и администрированием. В `client/` находится React + Vite + TypeScript + MobX; в `server/` — Node.js + TypeScript, API/SSE, SQLite, фоновые задания и CLI. Клиент и CLI используют одинаковые права и проверки сервера.

Публичного релиза ещё не было. Поддерживается один текущий API и формат данных; несовместимые данные и копии отклоняются без миграций. Обязательные правила — в [AGENTS.md](AGENTS.md).

## Первый запуск

Нужны Node **24.19.0** ([.nvmrc](.nvmrc)), Python 3.10+ и установленная локальная Ollama. Для OCR на macOS нужны Xcode Command Line Tools, на Linux — Tesseract с языковыми пакетами. Перед загрузкой модели запустите приложение Ollama или `ollama serve` в отдельном терминале.

Из корня репозитория:

```sh
node .yarn/releases/yarn-4.18.1.cjs install --immutable
yarn configure
yarn cli setup
yarn prepare:pdf
ollama pull qwen3.5:4b
yarn dev
```

Здесь и далее `yarn` означает закреплённый Yarn **4.18.1**. Если команда не установлена, заменяйте её на `node .yarn/releases/yarn-4.18.1.cjs` из корня проекта. `cli setup` готовит embedding-модель; администратора создаёт мастер, а не эта команда.

Откройте **http://127.0.0.1:5173/** и пройдите локальный мастер: создайте администратора, выберите каталог и лимиты, проверьте модели, создайте базу знаний и загрузите первый документ. Дождитесь индексации, задайте вопрос и откройте источник. Страницы PDF с OCR требуют проверки перед публикацией. Поддерживаются PDF, UTF-8 TXT и Markdown (`.md`, `.markdown`). Тестовые пользователи и документы автоматически не создаются.

Интернет может понадобиться для подготовки зависимостей и моделей. Дальнейшая работа использует локальные ресурсы. Для production-сборки сначала остановите dev-процессы, затем выполните `yarn build` и `yarn start`; клиент будет доступен на **http://127.0.0.1:8080/**. API на порту 3210 не раздаёт HTML.

## Возможности и ограничения

- Пользователь общается и читает разрешённые источники; редактор управляет назначенными базами; администратор управляет доступом, настройками, качеством и эксплуатацией.
- Поиск совмещает семантику, полнотекстовый поиск и точные идентификаторы. Источники сохраняют связь с версией, страницей и разделом. Вложения диалога остаются личными.
- Сервер сохраняет черновики, версии вопросов, выбранную ветку и состояние заданий. Ответы Markdown отображаются без исполнения HTML и сценариев.
- Согласованная SQLite-копия включает документы, пользователей, настройки обработки, историю и задания. Веса моделей и файлы окружения установки готовятся отдельно.

У сервера один writer SQLite. Семантический поиск перебирает разрешённые векторы; ANN и общий каталог нескольких серверов не реализованы. OCR и содержание ответов требуют проверки человеком. Контрольные вопросы сопоставляют ожидаемые источники и фразы, а не доказывают правильность произвольного ответа.
